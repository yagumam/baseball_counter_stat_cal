# 기록 함께 모으기 (구글 시트) 설치

앱의 설정 → "기록 함께 모으기"에 동의한 휴대폰은 분석용 표(pitches · plays · games)를 개발자의 구글 시트로 보낸다.
이 문서는 개발자가 시트를 한 번 준비하는 방법이다. 준비하기 전에는 앱에 이 항목이 보이지 않는다.

## 1. 시트와 스크립트 만들기

1. 구글 드라이브에서 빈 스프레드시트를 하나 만든다. (예: "야구맘기록지 모음")
2. 메뉴 **확장 프로그램 → Apps Script**를 연다.
3. `Code.gs`의 내용을 모두 지우고, 이 저장소의 `apps-script/Code.gs`를 통째로 붙여 넣고 저장한다.

탭(`pitches` · `plays` · `games`)은 처음 기록이 들어올 때 스크립트가 만든다. 미리 만들지 않아도 된다.

## 2. 웹 앱으로 배포하기

1. Apps Script 화면 오른쪽 위 **배포 → 새 배포**.
2. 유형 선택(톱니바퀴) → **웹 앱**.
3. 설정:
   - 다음 사용자 인증 정보로 실행: **나**
   - 액세스 권한이 있는 사용자: **모든 사용자** (앱 사용자는 구글 로그인 없이 보내야 하므로)
4. **배포**를 누르고, 권한 확인 창에서 내 계정을 허용한다.
5. 나오는 **웹 앱 URL**(`https://script.google.com/macros/s/…/exec`)을 복사한다.

`Code.gs`를 고친 뒤에는 **배포 관리 → 수정(연필) → 버전: 새 버전 → 배포**로 같은 주소를 유지한 채 새 버전을 올린다. "새 배포"를 하면 주소가 바뀐다.

## 3. 앱에 주소 넣기

1. GitHub 저장소 **Settings → Secrets and variables → Actions → New repository secret**.
2. 이름 `SHEET_SYNC_URL`, 값은 위의 웹 앱 URL.
3. **Actions → 배포 (GitHub Pages) → Run workflow**로 다시 배포한다. (다음 머지 때도 자동으로 들어간다)

로컬에서 시험할 때는 `.env.local`에 `VITE_SHEET_SYNC_URL=…`을 넣고 `npm run dev`. (`.env.local`은 커밋하지 않는다)

## 시트 모양

- 탭 이름과 열은 분석용 CSV와 같다. 열 뜻은 앱의 "변수 설명서 (코드북)"를 본다.
- 맨 끝 `device_id`: 보낸 휴대폰을 구분하는 무작위 값. 이름·전화번호와는 관계없다.
- 같은 `device_id` + `game_id`의 줄은 보낼 때마다 지우고 새로 넣는다. 그래서 시트에서 직접 고친 값은 그 경기가 다시 오면 사라진다. 손으로 고치거나 계산할 때는 다른 탭이나 다른 파일에서 한다.
- 탭의 머리줄이 앱의 열과 다르면 스크립트는 덮어쓰지 않고 거절한다. 형식 버전을 올렸을 때는 예전 탭 이름을 바꿔(예: `pitches_v1`) 두면 새 탭이 만들어진다.

## 알아 둘 점

- 웹 앱 주소는 앱 코드에 들어가므로 누구나 볼 수 있다. 스크립트는 내용 모양(앱 이름 · 형식 버전 · 열 수 · 값 종류)을 확인하지만, 마음먹고 엉뚱한 줄을 보내는 것까지 막지는 못한다. 이상한 `device_id`가 보이면 그 줄을 지운다.
- 남의 아이 기록을 받는 것이므로, 앱은 무엇을 보내는지 보여 주고 "동의하고 켜기"를 눌러야만 보낸다. 사용자가 "보낸 기록 지우기"를 누르면 그 휴대폰 줄은 시트에서 모두 지워진다.
- 시트 하나는 셀 1,000만 개까지 담는다. 공 표 한 줄은 46칸이라 대략 20만 개 공까지다. 그보다 많아지면 탭을 나누거나 데이터베이스로 옮긴다.
- 보낼 때마다 탭 전체를 다시 쓰므로, 줄이 아주 많아지면 느려질 수 있다.
